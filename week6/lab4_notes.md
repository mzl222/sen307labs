# Lab 4: Data Manipulation Language (DML) & Referential Integrity Notes

In Part 4, attempting to delete the 'Library and Information Science' department triggered **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails**. MySQL refused to execute the deletion because a child record in the `Student` table (`matric_no = '20239999'`, Transfer Student) still referenced that department's `dept_id`, and deleting the parent row would have created an orphaned foreign key and violated referential integrity[cite: 3, 4]. To resolve this safely without losing student data, I first ran an `UPDATE` statement to reassign the dependent student to the 'Software Engineering' department, after which the `DELETE` statement succeeded. Alternatively, I could have resolved the error by deleting the dependent student record from the `Student` table before deleting the department, or by configuring the foreign key constraint with `ON DELETE CASCADE` (to automatically delete dependent rows) or `ON DELETE SET NULL` (to clear the department reference) when defining the schema.
